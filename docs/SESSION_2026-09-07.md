## 1. Isaac parity — done

### The architectural decision

`bench/llm_client.py` and `sim/run_demo.py` stay separate but stop duplicating
the decision logic. They drive different execution models — `run_demo.py` calls
MuJoCo in-process, `llm_client.py` writes to `bridge/inbox` and polls
`bridge/outbox` while a separate process in `isaac6` executes — so merging them
into one file would mean editing the one demo path already verified on the Mac.
Instead `llm_client.py` now imports the same roster, legend, converters and
retriever `run_demo.py` uses. Drift surface goes to zero without a refactor.
`sim/run_demo.py`, `sim/sim_backend.py` and `sim/full_grasp_backend.py` were not
touched. `[Certain]`

### What was actually missing

Less than expected. `llm_client.py` already built its roster from
`all_clients()`, so rungs 3 and 4 were reachable — an earlier assumption that
the fix had landed only in `run_demo.py` was **wrong** and is corrected here.
`[Certain]`

Three real gaps:

1. **No legend.** `run_demo.py` calls `apply_legend("v5")`; `llm_client.py`
   never did, so rungs 3 and 4 ran on the v3 legend.
2. **No constrained decoding**, and it could not simply be copied: the schema_v2
   JSON Schema forbids every legal Isaac location.
3. **Rungs 1/2 were prompted in the backend's vocabulary** (`cell_R_C`) while
   rungs 3/4 ran canonically. So the demo's headline comparison — classifier
   beside cloud model on the same command — was not like for like, and neither
   the legend nor constrained decoding could reach rungs 1/2 at all.

### The fix

`--vocab canonical` (default on Isaac) prompts **every** rung in schema_v2 and
translates to Isaac names at the edge through the `to_backend_action()` path
rungs 3/4 already used. Nothing edits `schema_v2.json`; nothing touches the
30,352 measured rows. Both files' docstrings previously said not to unify the
vocabularies because it would mean editing `schema_v2.json` — that objection
does not apply, since this edits nothing. `[Certain]`

`--vocab backend` remains the default on MuJoCo, whose `table_*` names have no
schema_v2 equivalent.

Known cost: `handover` has no schema_v2 name and is unreachable in canonical
mode. `--vocab backend` still gets there. `[Certain]`

### Also changed

- **Push-to-talk voice.** `asr/voice.py` already supported it via `seconds=None`;
  the client hardcoded a 5-second window that cut people off. Now the default.
  `--seconds N` restores the fixed window for unattended runs.
- **Runtime symbols on Isaac.** `max_reach` and `nearest_free_cell` previously
  crashed the turn. Now resolved in `isaac_backend.resolve_runtime()`, mirroring
  `sim/workspace.py`'s rules exactly rather than inventing Isaac's own — the
  rules were checked to agree across 16 scenarios offline. Results report a
  `resolved` field naming the chosen cell. Verified live: "put the bottle
  anywhere you see free" → `resolved: cell_0_1`, 0.4 cm, ok. `[Certain]`
- **`move_to` convergence.** It was breaking on
  `controller.get_current_event() >= 1` — the moment `PickPlaceController`
  *leaves* its approach phase, not the moment the arm arrives. That phase runs a
  fixed number of steps from the controller's own schedule, so every call
  returned exactly **125 steps regardless of target**, stopped mid-approach, and
  reported whatever error it had. The old `ok < 0.08` gate passed 5.3 cm as
  success. Now watches the end-effector and stops on arrival, descent or stall.
  `[Certain]`
- **Visual table top.** A `VisualCuboid` with its top surface at exactly z=0, no
  collider — the `GroundPlane` already carries contacts at z=0 and a second
  surface at the same height would change how objects settle and invalidate the
  measured placement accuracy. No coordinate anywhere changes. `[Certain]`

### Guards added after a path audit

Enumerating all 16 `(backend, vocab, rung)` combinations found two dead paths,
both pre-existing:

- `--vocab canonical --backend mujoco`: 11 of 14 locations unexecutable.
- **any rung-3/4 model on `--backend mujoco`**: same 11, because those rungs are
  canonical by construction and have no prompt that could be switched.

Both now exit at startup with the reason. The interactive `model` switch
enforces the same rule. All eight Isaac paths reach 100% of their legal output
space. `[Certain]`

### Two false alarms, recorded because the pattern matters

**"V5 has a row defect."** "Move to the far left corner" returned `grid_C1` once,
and this was called a bug on **one sample**. Four follow-up commands
(far/near/upper/bottom) all returned correctly. The single inversion was
gpt-4o-mini non-determinism — §2.5 of the previous record already documents it
at 77.1% byte-identical across repeats with no seed passed. Calling a defect
from n=1 is the exact error the audit discipline exists to prevent. `[Certain]`

**"RAG is broken in `run_demo.py`'s default config."** `gpt-4o-mini/rag`
returned `reject` for a probe whose answer was literally in the retrieved
examples. Diagnosed through four wrong hypotheses (corpus gap, retrieval
failure, example-shape mismatch, rendering bug) before the prompt dump showed
the real cause: **the canonical legend has no colour glossary**, the probe said
"the red cube", and `reject` was correct. The bug was the selftest probe.
`run_demo.py`'s default was never broken. `[Certain]`

This is also a live-demo constraint: say "the rubiks cube", not "the red cube".

### `_GRID_COL` resolved

The column half of the grid mapping was an unverified assumption. Settled
physically: `put the red cube in cell 0 2` placed it on the side **nearest the
boxes**. Boxes are at y=+0.40, so Isaac column index increases toward +y and
schema column 3 ("right") maps there. `[Certain]`

That side is the **robot's own left**. So left/right are stated from the
operator's view facing the robot across the table — correct for an audience
opposite, mirrored for anyone behind. **This is a convention, not a fact, and it
needs one sentence in the thesis.** No code change; the current mapping matches
how the datasets were authored. `[Likely]`
